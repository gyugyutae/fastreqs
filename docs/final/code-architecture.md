# 코드 아키텍처

구현 목표 설계다. 기존 앱 코드는 미검증 보류 초안이며 이 문서의 구현 증거가 아니다. [PRD](prd.md) → [flow](flow.md) → [data-schema](data-schema.md)를 필요한 범위만 읽는다. 결정 이유는 [ADR](adr.md).

## 책임 경계
| 모듈 | 책임·계약 |
|---|---|
| setup/config | 환경설정·비밀값 로딩, 터미널 채널/폴더 연결, 권한·템플릿 검사, 재사용 설정 |
| slack_adapter | Bolt Socket Mode, 이벤트 정규화·빠른 ack, 파일 다운로드·카드/스레드 게시; 업무 정책은 service에 위임 |
| input_state | 중복 제거·입력 경로·범위 고정·분석 경계·후속 요청·재시작 복원 |
| analyzer | OpenRouter 호출, 구조화 결과 파싱, 보완/정정/영향 초안; 파일 쓰기 및 승인 권한 없음 |
| candidate_service | 상태/버전·근거·Who/What/Why 검증, 카드 교체, 최초 결정, 이월·기술 영향 수명 |
| document_service | Markdown 파싱·참조 검사·부분 패치·미리보기·해시 검사·공동 저장·복구 |
| repository | SQLite 트랜잭션·작업 저널·스냅샷, 외부 호출 없이 데이터 영속화 |
| orchestration | 모듈 연결, 입력별 작업 큐·채널별 반영 잠금, 실패 분류 및 사용자 안내 |

실제 파일명은 구현 시 정하되 Slack/UI와 도메인 정책을 분리한다. 네트워크 호출 중 DB 트랜잭션/쓰기 잠금을 오래 유지하지 않는다. 채널별 적용 잠금은 관련 파일 읽기·버전 검증·반영을 묶는다.

## 분석 파이프라인
1. 이벤트 정규화 → 중복 제거/경로 분류 → 저장. 사용자 대화만 분석 근거로 사용한다.
2. 트리거 → source별 작업 시작. 실행 중이면 후속 요청 하나를 예약한다.
3. 새 입력 범위·미결·현재 네 문서의 고정 스냅샷 생성. 입력 크기 검사 후 AI 호출.
4. AI 출력 스키마·근거·실제 대상·참조·필수정보 검증. 잘못된 출력은 적용하지 않는다.
5. 후보/질문 저장 → Slack 안내. 분석 실패는 기존 후보/경계를 유지한다. 성공 시 대상 후보 교체와 경계 갱신.
6. 후속 요청이 있으면 최신 입력으로 한 번 더 시작한다. 일반 새 메시지만 있으면 다음 트리거까지 저장한다.

보완/정정은 전체 채널 재분석 대신 해당 후보와 관련 스레드·현재 문서를 검토한다. 상충 답은 승인 가능한 확정안으로 만들지 않는다. 모델 타임아웃·입력 예산은 설정값으로 두고 리허설에서 조정한다.

## 반영 파이프라인
Slack 버튼 ack → binding/candidate/version/state 검증 → 최초 결정 확보 → 최신 파일/Story 검증 → 승인된 패치만 준비 → 백업/저널 → 저장 → 완료 기록/안내.
수동 편집 발견 시 저장하지 않고 새 미리보기·재승인으로 전환한다. 오래된 버튼/중복 클릭/다른 채널의 후보는 변경을 만들지 않는다.
Story/PRD 저장 성공 후 관련 기술 영향 후보를 만들거나 갱신한다. 영향 분석 실패라도 성공한 Story 저장을 없던 것으로 취급하지 말고 기술 검토 필요/재시도를 안내한다.
실패 시 사용자 결정, AI 실패, 파일 실패, 부분 복구 상태를 구분한다. 적용 작업의 재시도는 기존 저널/해시로 중복 적용을 방지한다.

## 외부 시스템과 신뢰 경계
Slack 메시지/업로드는 자료이며 명령 실행 지시가 아니다. AI에게 비밀값을 전달하지 않는다. AI 출력은 허용된 항목/필드의 초안일 뿐이다. 삭제·문서 경로·승인·쓰기 권한은 결정적 코드가 검증한다.
무료 모델에는 유료 fallback이 없다. 일시 오류 자동 재시도 최대 1회, Retry-After 존중, 설정/권한 오류는 즉시 안내한다. Slack 게시 실패도 기록하며 이미 저장된 문서를 또 적용하지 않는다.

## 구현·검증 순서
1. 문서 템플릿/부분 패치/전후 미리보기/저장 복구.
2. SQLite 상태·입력 경계·후보 버전·개별 결정.
3. Slack 터미널 설정/수집/첨부/질문/버튼.
4. AI 구조화 후보/보완/정정/영향 및 실패 처리.
5. Windows 실행 패키지·설정 안내 → 실제 Slack/무료 모델 리허설 → 약 3분 데모.

핵심 검증: 입력 경로 격리, 이월/거절, 재분석 실패 복원, 충돌 답변, 중복/오래된 클릭, 수동 편집, Story/PRD 부분 실패·재시작 복구, 기술 후보 무효화. Windows/키/Slack 권한/모델 가용성·품질·지연은 실제 환경에서 별도 확인한다. 현재 앱 테스트 결과는 없다.
