## 구현 설계안: 영속성과 직렬화
내부 상태는 SQLite에, 변경 전 파일 스냅샷은 로컬 복구 저장소에 보관한다. 추가 서버 없이 재시작/중복 결정을 보호하려는 선택이다. 입력별 분석은 한 번에 하나, 문서 반영은 채널별로 직렬화한다. 하나의 폴더를 여러 채널에 연결하지 않으며 봇 프로세스도 하나만 운영한다.
SQLite 트랜잭션과 파일 저장은 하나의 원자적 트랜잭션이 아니다. 작업 저널/백업/복구와 사용자 안내로 불완전 상태를 드러낸다. 세부 계약은 data-schema에 둔다.

## 변경 원칙
새 결정은 새 ID로 추가한다. 기존 이유를 삭제하지 않고 Superseded와 대체 ID를 연결한다. 단순 Story 변경에는 ADR을 만들지 않는다. 위 표는 FastReqs 설계이며 시연 제품의 adr.md와 별개다.
