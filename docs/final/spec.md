# FastReqs — Spec

상태: 설계 계약 1.0. 코드/실제 연결 검증 결과가 아니다.

## FR-US-001 채널 문서 연결
터미널에서 채널 링크/ID와 문서 폴더를 입력하고 workspace/channel→folder 연결을 저장한다.
대상 파일명: prd.md, user-stories.md, spec.md, adr.md. 연결 시 수정 없이 검사하고 누락/형식 오류 안내.
한 채널의 수정은 연결된 폴더에만 적용한다. 여러 채널을 같은 폴더에 잘못 연결하지 않도록 검사한다.

## FR-US-002 채널 분석 계약
사용자 메시지 수집, bot 메시지의 자기 트리거 제외, 동일 이벤트 중복 처리 방지.
멘션+분석 요청 또는 설정 종료 키워드 감지로 호출. 첫 입력은 수집 시작 후 대화.
성공한 분석에 사용한 메시지만 완료 처리. 실패 입력은 보존한다. 이후 새 메시지는 다음 입력으로 저장.
채널 입력의 미결 후보 및 현재 문서를 함께 참고한다. 파일 입력 완료는 채널 분석 경계를 이동하지 않는다.

## FR-US-003 파일 분석 계약
Markdown 메시지의 스레드에서 명시 요청. 파일/스레드 답변/동일 경로 미결 후보/현재 문서만 참고한다.
UTF-8 .md 하나/최대 1 MB/빈 내용 제외. 다운로드/검증 오류 안내. 전체 입력량 사전 점검 후 넘치면 분할 업로드 요청, 임의 절삭 없음.
같은 채널 동일 파일 내용은 기존 스레드 안내. 이름 동일/내용 다름은 새 경로. 채널 다름은 독립.

## FR-US-004 보완 계약
Story의 Who/What/Why를 근거로 검증, 부족하면 질문. 추측을 확정 정보로 채우지 않는다.
질문/후보를 스레드와 연결. 답변 즉시 해당 후보만 검토. 상충은 선택 질문, 해소 전 승인 보류.
한 번 보완했다고 무조건 완료하지 않고 부족하면 추가 질문한다. 승인 후 변경 요구는 새 수정 후보.

## FR-US-005 후보 구조/정정
입력경로, 후보 ID/버전, add/update/delete, 대상 Story ID, Story 내용, 근거, PRD 부분 변경, 관련 기술 문서 영향, 읽은 문서 버전, 상태.
수정/삭제 대상은 실제 존재하는 활성 Story로 검증한다. 정정은 새 버전의 후보이며 이전 버튼 무효화.
카드는 Story/PRD 변경 전후와 승인 범위를 보여준다. 인수조건은 검증 가능한 문장으로 제시하고 사용자가 검토한다.

## FR-US-006 승인 및 Markdown 반영
즉시 Slack ack, 채널/후보/상태/버전 확인 후 해당 후보의 최초 결정만 반영.
Story 및 PRD 변경을 함께 미리보기하고 한 승인 단위로 처리. 기존 제품 목표/배경/무관 섹션 보존.
삭제는 활성 항목 제거, 이전 내용/근거/처리자/시각 내부 보존. ID 재사용하지 않음.
거절은 파일 변경 없이 기록. 완료 안내는 두 파일 저장 성공 후.

## FR-US-007 Spec/ADR 계약
관련 Story ID로 영향 추적. 실제 영향 있는 후보만 별도 승인.
Story 변경만으로 기존 Spec/ADR 전체 재작성하지 않는다. ADR 새 항목, 이전 기록 보존, 대체 관계 표시.
새 일반 분석은 기술 문서 후보를 폐기하지 않는다. 관련 Story 변경 승인 시 오래된 후보 적용 차단/새 후보.
미결 또는 거절된 영향은 갱신 검토 필요로 표시하며 명시적 재검토 없이 거절 후보를 되살리지 않는다.

## FR-US-008 상태와 대기 처리
Story 미결은 입력별 이월. 승인 완료는 현재 문서로 참고, 거절은 이월하지 않음.
대상 재분석 동안 승인/거절 보류. 문구: "재분석이 끝나면 새 제안을 확인해주세요".
새 분석 성공 후 이전 후보 대체, 실패하면 이전 후보 다시 결정 가능.
진행 중 새 트리거는 입력경로별 후속 요청 하나로 묶는다. 현재 분석 취소하지 않음.

## FR-US-009 지속성과 복구
DB에는 대화/후보/버전/결정/이월/대기/복구 이력, Markdown에는 기준 요구사항 및 문서 내용.
재시작 시 저장 자료/연결 복원, 최신 파일 확인. 과거 미수집 대화 자동 조회 없음, 수집 재개 시점 안내.
승인 전 수동 파일 변경을 확인해 최신 미리보기 재승인. 저장 직전 변경 검사도 필요.
변경 전 내용/작업 기록 보존. Story/PRD 두 파일 준비/반영. 일부 실패 시 원상복구 시도.
복구도 실패하면 부분 반영/복구 대상 안내. 여러 파일에 완전한 원자적 저장을 보장한다고 표현하지 않는다.

## FR-US-010 모델 및 오류
OpenRouter: nvidia/nemotron-3-super-120b-a12b:free. 설정에서 모델 교체 가능하나 유료 자동 전환 없음.
AI 결과는 구조/대상/필수정보 검증 후 후보로 저장. AI가 직접 파일을 쓰거나 승인하지 않음.
일시적 오류 자동 재시도 1회, 호출 제한의 대기시간 존중, 설정/권한 오류 안내, [다시 분석].
실패 범위를 완료 처리하지 않고 미결/입력을 유지. 재시도 루프 무제한 실행하지 않음.

## 구현 시 결정/검증할 세부값
입력 토큰 예산/타임아웃/대기시간, API 모델 지원/한도/지연, Slack 권한/첨부 다운로드, Windows 실제 실행, 파일 부분 수정/저장 복구.
자격정보는 로컬 설정하며 문서/로그에 키 자체를 출력하지 않는다.
